# src

## Purpose

All engine, terminal UI, and live-control code for the nooise binary.

## Ownership

- `main.rs` — binary entry point: CLI parsing (`run`/`version`/`update`/`render`/`auto`/song code), wires up terminal + audio engine. `-M`/`--start-muted` is live-only and opens with Master Level at 0%. `--output-device <NAME>` selects an exact output name for live playback; `--audio-devices` lists current outputs without starting audio or the terminal.
- `update_check.rs` — passive crates.io update notification helper; checks in the background and exposes a short TUI-safe message.
- `audio.rs` — cpal output ownership, typed `OutputSelection` (`SystemDefault` or exact device name), and the shared `OutputRouting` handle outside musical state. The audio owner discovers devices at startup, on CoreAudio device/default-output notifications, and on picker refresh requests; idle ticks never query device names or enumerate outputs. CoreAudio callbacks only advance a static notification revision, and the audio owner unregisters listeners on exit. Other backends use picker requests and stream-error recovery. A picker freezes the latest catalog and requests a background refresh for subsequent openings. Switch success/failure is reported through routing notices. Missing or ambiguous explicit names are errors, never a fallback to another output. Failed switches retain the current stream and retry. Matching-rate rebuilds reuse the live engine; a generation gate lets only the active stream advance it. Callbacks use `try_lock` once per buffer and emit silence on contention, never wait. A sample-rate change rebuilds the engine and reports the restart. `StereoEngine::begin_buffer` receives cpal's playback latency. Output buffers request 256 frames clamped to the device's advertised range.
- `fluid/` — the core engine module:
  - `mod.rs` — crate-facing glue: `run()` (TUI + live audio, with independently randomized built-in Pad progression and Tonal Phrase selections for a fresh session), `run_auto()` (TUI + live audio, slow-morph mode), `render_wav()` (headless wav render), `FluidTelemetry`. `-M`/`--start-muted` sets Master Level to 0% across a live start and every auto-morph endpoint, so a morph cannot raise it. Explicit songs and auto endpoints keep their authored musical selections. Headless default renders remain deterministic. Also the shared numeric helpers every submodule reaches through the `use super::*` prelude: `smoothstep` (the one ease behind ramps and LFO glides) and `splitmix64_mix` (the one finaliser behind RNG-free seeded values).
  - `auto.rs` — `nooise auto --bars BARS`: `AUTO_STATES` baked-in share codes decode to a `Vec<SongState>` at startup (fatal on a bad code); `MorphState` holds the decoded endpoints — each a full `SongState` (controls + automation) — plus a precomputed schedule of phrase-rounded holds and crossings, deriving progress purely from the live beat clock; `MorphWriter` updates controls and automation on the transport eighth-note grid, with immediate section-boundary updates.
  - `controls.rs` — `FluidControls`, `MasterControls`, and per-voice control structs with defaults.
  - `registry.rs` — the control registry: one `ControlSpec` table per tab (stable ID, label, kind, range, step, entry semantics, reset, accessors, display). `tab_controls`/`apply_delta`/`apply_reset`/`apply_value` all derive from it. Randomization uses each control's contextual dial; singleton ranges stay unchanged. Rows matching a common archetype use the one-line macros `gain_pct!`/`time_secs!`/`time_ms!`/`beat_interval!`/`beat_offset!`; a row deviating from its archetype in any field stays a plain `ControlSpec`. Each tab's table is one `layer_controls!` invocation listing only that layer's own base rows — the macro appends the shared tails (`chord_slot_rows!` for Pads, then `module_slot_rows!` for all eight slots), so no table hand-expands a slot row. Voice-type labels come from one `&[&str]` table per voice (`PAD_TYPES`/`BASS_TYPES`/`KICK_TYPES`/`TONAL_SYNTH_TYPES`) read through the shared `type_label`/`wrapped_index` (the one float-to-table-index wrap; Bass rhythm, Tonal phrase, and Arp pattern wrap the same way into their own tables), and each table-indexed control's `max` is `last_index_of` its table so range and labels cannot drift apart. Per-tab metadata (name, mute-target level id, control table) lives in the single `TAB_META` const, in discriminant order (test-enforced).
  - `automation/` owns bounded automation stacks keyed by stable control ID. `lfo.rs` owns shapes, fields, rate pickup, the `Ramp` shape (one shape for every sawtooth and triangle: Curve, Skew and Anchor rows follow Shape only while it is selected; Skew is the rising fraction so 100% is ramp up, 0% ramp down, 50% triangle; Anchor is bipolar like Curve and places the travel against the base: 0% centres it, +100% lifts it above the base, -100% ducks it below; amount is the whole travel, so a centred ramp swings half what a sine of the same amount does), and the inline `Steps` staircase, whose step values are bipolar (-100..+100%, 0 centred: positive steps lift the control from its base, negative steps pull it below). `envelope.rs` owns triggers and envelope fields. `mod.rs` owns shared addresses, lane storage, position-space summing, morphing, and the audio-side de-clicker. Each control can carry up to four LFO lanes and four envelope lanes. Lanes sum before one clamp/snap/de-click pass. Song code persists stacked lanes by repeating the control address in the existing container-v2 route records. Shape tags are append-only; tags 1-3 (Triangle, RampUp, RampDown) are retired into Ramp (tag 8, which carries its three sub-knobs) and refused as `RetiredControl("triangle/ramp lfo shape")`.
  - `song.rs` — binary song-code export/import for controls, automation, mute state, and runtime-session records; owns the container version and every value encoding. `Ctrl+S` copies only the raw `n1_…` code and shows a short confirmation; `nooise <code>` or `cargo run -- <code>` applies the decoded song state before audio/TUI startup.
  - `range_epoch.rs` — the dial-range epoch table (`RANGE_CHANGES`, append-only), and `stale_modulation`, the decode-time refusal check.
  - `song_ids.rs` — `SONG_ID_TABLE`, the append-only control-id ↔ `u16` index mapping song codes intern against, plus `song_id_index`/`song_id_at`. Never reorder, remove, or reuse an index; append only. Deliberately not derived from `all_specs()` so registry order stays free to change.
  - `osc.rs` — opt-in bidirectional OSC feed (bare `--osc` targets `DEFAULT_OSC_TARGET` 127.0.0.1:9000, foorm's default; `--osc=ADDR` overrides; bare `--osc-in` listens on `DEFAULT_OSC_LISTEN` 127.0.0.1:9001; `--osc-in=ADDR` overrides). `OscEmitter` reads `FluidTelemetry`, `SharedOscUiState`, and the audio engine's `OscVoiceEvent` stream on its own thread and preserves the legacy beat, level, chord, kick, and gesture addresses, plus `/nooise/chord/span`, `/nooise/chord/change`, `/nooise/hit/<source>`, `/nooise/voice/{pad,arp,lead,bass}/*` note events, and `/nooise/state/{cursor,layer/*,page_rows,pad_window,steps}`. `OscReceiver` listens on UDP and parses `/nooise/cmd/*` messages into semantic UI commands (`OscUiCommand`, applied on the coordinator turn loop) and low-latency voice note commands (`OscVoiceCommand`, drained on the audio engine's control tick). The audio thread never waits on UDP, and an absent consumer is never an error. The ignored `song_level_profile` test prints a per-voice RMS table for a built-in song (`NOOISE_SONG=12 cargo test --release song_level_profile -- --ignored --nocapture`).
  - `link.rs` — opt-in Ableton Link (`--link`, `rusty_link`, GPL-2.0-or-later), compiled only under the off-by-default `link` Cargo feature. Every consumer (`TempoClock::link`, `with_link`, `begin_buffer`, `follow_peer_*`, the UI-loop follower, `LiveStartOptions::link`, the Link tests) is `#[cfg(feature = "link")]`; the `--link` flag exists in every build and `main` refuses it when the feature is off. `cargo_install_args` carries the feature so `nooise update` keeps it. `LinkSession` joins with start/stop sync on; `LinkClock` is the audio-side timeline reader/writer inside `TempoClock`; `LinkPeerChanges` hands peer tempo and start/stop to the UI thread; `LinkFollower` applies them each UI tick. See the Link contract below.
  - `palette.rs` owns the static `/` catalog, complete-query projection, and empty-query global MRU ordering. `palette_search.rs` ranks separate semantic metadata by exact ID/name, word/prefix/fuzzy meaning, owning scope, declared default, spelling, recency, and stable identity. Display descriptions, formatting, and live values never rank.
  - `operation.rs` owns the closed palette operation vocabulary and its labels, aliases, and descriptions for recipes, mix actions, Motion, and planned mute. Confirmation resolves typed interaction effects; the executor never dispatches string commands. Ordinary LFO/envelope lane actions retain their lifecycle catalog.
  - `mix_action.rs` — static global mix-action catalog, separate from knob recipes. Kick Only (aliases `kick only`, `solo kick`) and Mute Kick (aliases `mute kick`, `kick mute`) are offered globally and in scoped palettes. Confirm publishes one mute snapshot immediately: Kick Only unmutes Kick and Master and mutes every other voice; Mute Kick sets only Kick muted, preserving every other mute including Master. Repeating applies the same state; there is no restore toggle. Levels, automation, auto, transport, navigation, and MRU stay unchanged; an open automation editor resumes after the palette closes. Tab completes the action name without numeric entry.
  - `recipe.rs` owns the static `RECIPES` table and its ordinary LFO templates. Sway is an 8-beat sine; Tremolo is a half-beat sine; Pulse is a one-beat square; Drift is a four-beat RandomDrift with a fixed seed; Rise is an 8-beat Ramp lifting from the base (anchor +100%). All start at zero depth and leave the target base unchanged. Tremolo is idempotent for its authored shape and cycle after Amount edits, so repeat input leaves one tremolo LFO; other recipes stack lanes. Sidechain (alias `sc`) is a one-beat Ramp anchored below the base (anchor -100%) at zero depth without moving the base; raising Amount dips below and recovers to the base, never overshooting it, before the existing smoothed wrap. It follows transport beats independently of Kick hits, offset, or mute. Repeating stacks another silent lane. Depth is dial-position distance; ordinary base and lane controls persist, with no recipe identity.
  - `capture.rs` owns bounded manual edit history and transport-aligned Motion loops. Grab supports 4/8/16/32 beats and sixteen loops total. Numeric controls and continuous editor fields store relative curves with a normalized reference taken from the successful publication's authored base. Curves use eight u8 positions per beat through sixteen beats, four per beat at thirty-two, and at most 128 positions. Discrete controls, LFO Shape, envelope Trigger and Steps Count store absolute choices: at most 128 exact events on a 1/256-beat grid. Both representations hold their terminal value until wrap. History retains sixteen recently edited registry targets and sixteen editor fields, at most 4,096 edits each over 64 beats. Registry history and frozen palette targets distinguish permanent chord progression identities; selecting a progression does not fabricate edits to its chord fields. Playback still addresses the selected progression's bank. Editor history clears the affected family after an observed lane insertion/removal/reindexing or module replacement; ordinary numeric, Shape and Trigger edits remain capturable.
  - `chassis_tap.rs` — opt-in Apple Silicon chassis accelerometer reader for `--chassis-tap`, plus the pure three-to-five-tap median BPM fit. Its IOKit callback sends only accepted timestamps to the UI thread; it never waits on or mutates the audio thread. The live-only tap history is deliberately not encoded in song codes.
  - `interaction.rs` — pure semantic interaction model: cohesive navigation, exclusive keyboard-owning modes, input-phase policy, deterministic transitions, and ordered effect values.
  - `runtime.rs` — Crossterm-only terminal adapter and deterministic fair scheduler: capability negotiation, transport normalization, typed semantic/deferred mapping, bounded input admission, tick cadence, and frame deadlines. Its test-only `recording` module is the single writer of the replay fixture grammar (`SanitizedTraceRecorder`, key/phase tokens) and owns the transport test scaffolding shared with `replay.rs`: `FakeClock`, `TerminalCapabilities::full`, `TransportEvent::key`.
  - `replay.rs` — test-only production-path replay harness: sanitized raw-event fixtures (parsed here, written via `runtime::recording`), the scripted input adapter, shipped raw performance phase fixtures, exact binding postconditions, the shared production coordinator/tick seam, real scheduler/normalizer/kernel/effect/view/render traversal, and model-based invariant tests.
  - `effect.rs` — ordered interaction-effect execution: aggregate control/automation/mute edits, auto exit, unit state, MRU/selection consequences, staged bar commits, clipboard, and typed acknowledgements/failures that keep interaction ownership synchronized. Every bridge runs its effect list through the one `run_ordered` helper, and the arms that mutate automation go through `with_automation`, which loads the frame's automation once and acknowledges the generation the edit published. Effect execution calls *down* into `edit.rs` for those mutations; it must never call into `ui.rs`.
  - `session.rs` — immutable `LiveSessionSnapshot` (controls, automation, tonal state, mute state, planned boundary action, transport) plus its single CAS-retry `ArcSwap` transaction boundary. Its audio-clock marker gives exact-boundary actions to rendering once playback starts.
  - `planned.rs` — typed next-bar actions held in the live session. The first action is a layer mute; it is rebased to song beat zero when saved. The audio engine leads its click-free ramp into, then commits it on, the exact downbeat; the production tick catches up only when audio is absent.
  - `view.rs` — cohesive immutable `UiViewModel` projection from interaction ownership, one live-session generation, telemetry, and presentation-only state; owns typed help/notice precedence and the minimum terminal contract.
  - `ui.rs` — pure Ratatui rendering from `UiViewModel` and the frame area, and nothing else: it must not mutate session state, execute effects, or poll input. `render` derives one `PanelFrame` per frame (open modulator surface, numeric entry, `ModContext`, live chord slot, bar width) and composes the panel from `draw_scrim`/`draw_breadcrumb`/`draw_control_rows`/`draw_activity`/`draw_footer`/`draw_palette`/`draw_help`, so every section reads the same frame. The footer is two stacked rows: `draw_activity` renders `UiViewModel::activity` (dim idle key hints, or a bold live readout when `activity_live`) above `draw_footer`'s stable exits/mode-help/notice line, so gesture text never replaces the other footer content. `draw_help` is the static keyboard-shortcut overlay (`ModeSurface::Help`): it covers the breadcrumb/control area but stops above the activity and footer rows, so those stay visible under it — the same pattern the palette uses to keep its own exits in view. The chord editor title uses the padding row below the breadcrumb, preserving the two persistent harmony header rows. Owns the control/modulator row widgets, the shared `lane_line` both modulator lanes render through, slider markers, and the flipped display-unit (`FlippedUnits`) formatting.
  - `coordinator.rs` — the shared production turn coordinator (`coordinate_production_turn`/`_event`/`_action`/`_tick`) plus the live `production_ui_loop`. `coordinate_production_action` is the only path from a semantic action to the kernel and effect executor; its shared navigation upgrade resolves Touch/Cancel for keyboard and OSC, including Hub layers and progression slots. OSC gesture press/release/all-release also pass through this kernel path and its mode ownership and latch rules; replay tests that inject an action directly call it against a `production_frame`, never a private copy. Scheduler-due ticks commit before that turn's events, and the live scheduler loop and the replay harness both cross this same ordering seam. Opt-in live sources (chassis tap, Link) reach the loop as one `LiveAdapters` value.
  - `edit.rs` — every control and automation mutation a UI gesture performs: adjust/reset/set, unit flips, route removal and reseeding, and opening a modulator editor. `active_field` resolves the cursor to exactly one target, and `with_active_field` applies one `FieldOp` (`Adjust`/`Reset`/`Set`) to it, so the three verbs cannot drift apart; Delay's time rows step through the registry like any other (`contextual` supplies the loaded clock's grid); only the clock row's Sync/Free arrow flip is Delay-specific (`apply_delay_row`), and a Filter Type edit replays through `switch_filter_type` so the cutoff follows a Low/High flip. `effect.rs` calls into this module, never the reverse.
  - `visualizer.rs` — the ripple visualizer: `RippleField` (telemetry-driven animation state — field time, live kick ripples, chord hue), the `FluidWidget` that draws it, chord hues, and the `fluid_hsv`/`darken` colour helpers. Presentation only; it never reaches the audio engine.
  - `module.rs` — per-layer module slots: the `ModuleKind` catalog, `Domain`/`Family`, and `ModuleSlot`/`LayerModules` state. A slot stores *which* module is loaded as a value; the catalog never appears in a control id. Filter is a post-synthesis module with amount, cutoff, resonance, and type; Perc, Bass, Kick, and Clap ship with factory Filter slots instead of bespoke filter controls.
  - `widget.rs` — `Dial`/`DialScale`, the shared slider vocabulary every bar renders through. Owns all value-to-bar-position mapping and tapered position stepping; no other module derives a ratio.
  - `engine.rs` — `FluidEngine` (voice mixer), control smoothers, tempo clock and its `Transport`, grid triggers, shared per-layer/master effect bank, master bus, and the Master-bus gesture stage. `engine/gesture_audio.rs` owns its bounded gesture processors; see `fluid/engine/AGENTS.md`.
  - `gesture.rs` — normal-browsing gesture vocabulary and one fixed scalar envelope per gesture, all over Master. Amounts are evaluated from monotonic audio seconds, independently of tempo, key repeat, or UI cadence.
  - `gesture_level_probe.rs` — real-playback-level Master headroom renders: a clamp-hit regression bound, plus an ignored table of every song with each gesture held at full throw.
  - `fixtures/chord_legacy.txt` records 2,160 source-note results from the original Custom builder: degree, accidental, quality, extension, inversion, then four MIDI notes. Keep it independent of the current builder; `shared_builder_preserves_every_legacy_custom_choice` checks it.
  - `voice/` — one module per voice (pad, bass, perc, kick, tonal, clap, arp, lead) plus `voice/chord.rs` (shared allocation-free chord builder and derived chord names), and shared helpers (`midi_to_hz`, `tune_ratio`, `note_hz`, `soft_clip`, `normalized_lfo`, `mix_and_retain`/`mix_and_retain_mono`) in `voice/mod.rs`.
- `fx/` — shared DSP building blocks (LFO, panner, reverb) consumed by voices. See `fx/AGENTS.md`.
- `synth/` — shared synthesis primitives (envelope, oscillator, noise, multi-operator FM) consumed by voices. See `synth/AGENTS.md`.

## Local Contracts

- Manual edit history uses the before/after Arc pair returned by `LiveSession::transact_with_before`, so CAS retries never attribute another writer's changes to the edit. Known scalar registry edits use `EffectExecutor::edit_control_session` and direct `CaptureHistory::record_changes` lookup; coupled chord/module edits and arbitrary aggregate closures retain full discovery. MRU identity alone is not a change-set hint. Registry ID lookup caches the first spec per ID; editor capture suspension splits lane and clip borrows without copying automation.

- `visualizer.rs` precomputes separable wave factors per row/column and culls ripple tails outside three Gaussian widths. The panel keeps the moving base tint but skips hidden ripple and glyph work. Only background RGB is quantized to four-code buckets. `RippleField` memoizes presentation cells by area, panel, transport, hue and field time; stopped backgrounds refresh at most 10 Hz, while simulation ticks and foreground/input scheduling retain their normal cadence. Resize and transport changes invalidate the cache immediately. No musical state is cached or persisted here.

- `/output` and `/device` resolve `Operation::OutputDevice` through `EffectExecutor` into a device picker. `PaletteMode::output_choices` freezes the catalog for both rendering and confirmation; refreshes cannot change a selected row's identity. Enter requests the named output or System Default; Escape cancels. Routing bypasses `edit_session`, preserving auto, Motion history, MRU, navigation, and song codes. Catalog lookup never runs on the UI thread. Production and tests use the same picker path.
- Navigation queries use `view::navigation_control_ids` and the registry row-spec selectors shared with rendering; they never format display strings or project a full view. `UiViewModel::project` runs once per rendered frame, not per terminal event or OSC step.
- Visible row positions are never control-table positions. `ProductionFrame::selected` is an optional index resolved by stable ID; unresolved IDs stay `None`. `edit.rs` refuses unresolved base-control edits before any session publication or auto exit; automation editor fields retain their own address resolution.

- `OscUiPublisher` publishes only after navigation, mode, session generation, or auto ownership changes. The OSC emitter retains snapshot Arcs; playback-derived planned-mute countdowns and active chord slots are evaluated from telemetry without rebuilding snapshots. Periodic full broadcasts still recover late/reconnecting consumers without cloning UI state. Fixed level, gesture, hit, and layer addresses use static tables.

- OSC phrase events come from the sounding Pad `ProgressionCursor`, not a beat-divided guess or UI snapshot. `/nooise/phrase/reset` precedes `/nooise/phrase` on initial play, transport restart, progression switch, and morph landing. `/nooise/phrase` carries zero-based cycle and chord indices plus the current window count; it advances only at Pad chord boundaries and stays quiet while stopped. The existing chord addresses fire on each published chord, including the opening chord and a restart of the same slot. Publish atomic payloads on audio and encode/send only on the OSC thread.

- `ui.rs` header (`HeaderRows`): home key, sounding chords, chord ribbon (or the chord editor title), layer breadcrumb, then controls. From `HEADER_ROOMY_HEIGHT` rows of inner height, blank rows separate the harmony, ribbon, and breadcrumb groups; below it the header packs tight so the 46x11 minimum keeps its control rows. The read-only chord ribbon shows the sounding chord's span (`ChordSpan`: start beat and length from the pad's `ProgressionCursor`) as measures of four beats, one block per beat: dots ahead, a full block as each beat arrives, amber on the current beat. A four-beat chord is one measure, eight is two, sixteen is four; longer chords show the 16-beat page under the playhead. The pad engine publishes the span through `publish_chord_span` (a seqlock, so start and length read as a pair) whenever it changes, ahead of any chord onset, so the span is known before the first chord boundary. The ribbon adds no controls, clocks, or saved state.

- Motion is the palette name for retrospective knob loops. `Motion Grab 4/8/16/32` names beats; descriptions and aliases name the corresponding one/two/four/eight bars. `Space 1/2/4/8` grabs those bar counts on the selected control or LFO/envelope editor field. The nearest bar is both history end and phase anchor: a future anchor queues, a past anchor joins the running phase. The palette freezes its history endpoint and target. Motion Record and shared lane editing remain deferred; future state marks need another route. Do not expose `/capture`.

- `automation/lifecycle.rs` owns typed `/bypass`, `/resume`, and `/delete` actions on the open LFO/envelope lane. From an automation editor, the palette freezes that lane's control, family, index, module topology, and live-only `automation_revision`; any authored lane-stack change invalidates the target, including delete/re-add, while editor changes, LFO pickups, captures, and unrelated controls do not advance that revision. A stale action publishes nothing and asks the player to reopen `/`. Bypass/resume return to the same editor; delete removes the selected lane and returns to browsing. In browsing, Motion lifecycle actions address the selected knob's loop.
- LFO and envelope `enabled` defaults true and is independent of amount, editing, randomizing, and lifetime. Bypassed lanes retain their settings and count toward the four-lane family limit. Shared audio/UI summing excludes them; resume joins the current transport phase immediately through the existing de-clicker, and envelope Once does not retrigger. The UI shows a flat bypassed lane and a compact `bypassed · /resume` owner footer at 46x11; automation-owner action failures remain visible. Morphing selects enabled with the structural endpoint. Song record 9 stores only nonzero per-control disabled-lane masks (u16 control ID, four LFO bits, four envelope bits), applied after all lane records decode. Missing records mean enabled; duplicate records/targets, empty/trailing data, out-of-range masks, missing lanes, unknown IDs, and inactive module targets are refused, while retired IDs retain their specific refusal. The live revision never persists.

- Motion lives in `AutomationState` as typed relative samples or absolute events. Relative playback adds `sample - reference` to the current authored base, then sums other lanes before one clamp/snap/de-click pass. Editing the base preserves the loop, its reference and phase; the selected-row activity says `shifts with base`. Absolute choice playback preserves enum identities and a direct edit bypasses it (`edit bypasses`). Bypass returns to the edited base; resume admits the retained phase on the next bar. Registry and editor markers use the same effective lanes and single-clamp sum as audio; Steps playheads follow the effective lane. Audio caches one authored scalar per editor Motion target at plan rebuild and never feeds its output back or clones lane ownership per sample. Only manual session edits enter history. Module replacement clears the slot's loops. Transport restart resets phase without changing payload or enabled state. Registry record 8 uses Motion version 6; editor record 12 uses version 3. Both persist duration, typed data/reference, enabled state, phase and admission delay rebased to beat zero. Older payload versions are explicitly refused, malformed current data is rejected, and module/lane/range validation still applies. Morphing snaps both maps with the structural endpoint. The code-size regression measures four eight-bar curves under 2,000 characters and sixteen maximum-density curves/events against explicit larger bounds atop the largest built-in; it is not a universal maximum song length.

- UI interaction work follows `docs/adr/0001-unidirectional-interaction-architecture.md`: raw terminal input normalizes to semantic intents, one exclusive interaction mode owns the keyboard, pure deterministic updates emit ordered effects, and rendering consumes one immutable view model. Coherently coupled controls, automation, and user-audible runtime state publish as one aggregate `ArcSwap` snapshot through one transaction boundary; audio reads stay lock-free. The runtime must bound input work and complete visible frames within 50 ms of application-controlled time during continuous input.
- `fluid/interaction.rs` is the terminal-independent interaction kernel. `InteractionMode` is the only keyboard owner; mode-local data stays inside its enum variant. `PaletteMode` owns its query, selection, recents, locked value entry, and staged edits so no parallel palette overlay state can exist; selection wraps over the projected registry matches, invalid locked entry indexes are safely discarded, and confirm emits typed jump/commit payloads rather than requiring adapter-side reconstruction. `InteractionMode::Performance` is the Jump leader: Space owns the one-shot interaction and repeated activation is idempotent; a layer key (`INSTRUMENTS`) opens that layer at its remembered row and immediately hands the keyboard back to Browsing. A parameter key (`PARAMETERS`) with no layer key aims at the page already open, which is why `jump_effect` takes a `Tab` rather than a `PerformanceInstrument`: the shorthand reaches every layer, including Lead, the one page no selector key names. The selector keys read down the hub's layer rows (`asdf` then `qwer`, `r` on the hub), so their positions mirror the layers on screen. Layer and parameter routes move the cursor. `Space m` arms or cancels next-bar mute; `Space 1/2/4/8` grabs Motion on the selected control or editor field. Field grabs and cancellation return to the same editor row; other completed routes return to Browsing. All routes use Press edges without a capability branch or hold state. `jump_effect` is the only place a parameter becomes an address: Volume is the layer's own `Tab::level_id` row as `InteractionEffect::JumpToControl`, Filter is `FILTER_MODULE_ID` in `MODULE_CATALOG` as `InteractionEffect::PlaceFilterCutoff`, which the adapter resolves to add-or-jump and opens on Cutoff because only it can see whether the chain already holds one. Normal browsing owns temporary `z/c/v/x` gestures without entering a new mode; their input latches track physical holds and quarantine keys across mode transitions. Shift+P is `ToggleTransport` (plain `p` is unassigned), owned by Browsing and Automation like mute. `Intent::phase_policy` decides whether Press, Repeat, or Release is accepted before a transition runs. Every `Intent` also declares its owners in `Intent::handled_by`; both matches are exhaustive over `Intent`, so a new variant must decide its phase and its modes, and each mode's transition function guards on that ownership instead of restating what it ignores. `InteractionModel::update` dispatches one function per `ModeKind`, which report their next keyboard owner rather than assigning it. `LAYERS` is the single layer table: page order, page↔tab translation, and the navigation each page opens all index it in `Page`/`Tab` discriminant order (test-enforced). The hub (`Navigation::Hub`, the Master page and the default navigation) is not a layer: the `LAYER_COUNT` layers precede it in `LAYERS`, and its first `LAYER_COUNT` rows are their level rows in the same order (`hub_rows_open_with_every_layer_in_page_order`), so `hub_layer` translates a hub row to its layer by index. Enter on a layer row maps to `EnterLayer`; `m` there mutes that layer, resolved in the kernel into `InteractionEffect::ToggleMute(Tab)`; Tab/Shift+Tab (`Page::next`/`previous`) cycle every `LAYERS` page, the hub after Lead, so arrows and Tab alone reach Master's rows (`tab_cycles_every_layer_then_the_hub`); Esc pops the innermost drill, then from a layer's root returns to the hub on that layer's row. `LayerRows` records each layer's root row whenever navigation leaves its page (`update` and `select_control`), and every layer opening (Enter, Tab, the Jump leader's layer key, `i`) resumes on it. It is session-only navigation context, never persisted. `INSTRUMENTS` is the single performance-instrument table (selector key and page, in `PerformanceInstrument` discriminant order, test-enforced) and `PARAMETERS` the single jump-parameter table (key and footer word, in `PerformanceParameter` discriminant order, test-enforced); the runtime key map and the footer read both rather than restating the layers or the parameters. `InteractionMode::Lead` is the Lead play keyboard: `i` from any page opens it (`EnterLeadPlay` lands navigation on the Lead page first, so the rows it edits are in view), as does Enter on the Lead page (any row that is not a module drill or the `Pattern ›` row — the coordinator upgrades `TouchSelected` there, after the module check; on `lead.pattern` it becomes `EnterLeadPattern` instead), inside the pattern drill included. Holding follows the shared capability rule: where the terminal reports releases (`TerminalCapabilities::supports_holds`) a press is `PlayLeadTone { hold: true }` and the key-up is `ReleaseLeadTone`, so the note sustains under the finger; only the key that owns the sounding note releases it. A reduced terminal (no releases, autorepeat arriving as presses; plexi panes today) gets `hold: false` attack/decay taps and the LEAD footer says so, since the kernel cannot tell a repeat from a re-press there. `InteractionMode::Help` is the static keyboard-shortcut map: `Intent::OpenHelp` (Browsing-only) opens it on Shift+/, matched against whichever of the two reports a terminal sends for that chord — the shifted glyph `?` alone (no SHIFT modifier; terminals don't synthesize one for punctuation the way crossterm does for letters via `char::is_uppercase`), or the base key `/` with an explicit SHIFT modifier (the keyboard-enhancement protocol's report-base-key-plus-modifier style) — so a plain unshifted `/` still reaches `OpenPalette`. Ctrl+S/Ctrl+Q/Ctrl+C are global for every owner except the palette (its own control chords) and numeric entry (swallows every chord), so no mode traps the user. The runtime and the view both read `LEAD_PLAY_KEYS` and `LEAD_NUDGES` rather than restating the rows. `InteractionModel::update` remains deterministic and returns ordered data-only effects; adapters execute those effects elsewhere.

- A song code has two version axes, and Motion and chord-override records also version their payloads. The container version dates the byte layout. The dial-range epoch (`RANGE_EPOCH_RECORD`, `u16`; absent means 0) dates what a stored modulation depth means: depths are fractions of a dial's throw, so a range change moves them even though values stay in their own units. Every encode writes `CURRENT_RANGE_EPOCH`. Decoding refuses a code from an older epoch whose automation targets a dial `RANGE_CHANGES` lists as changed since, with `SongCodeError::StaleRange`, the way a retired control is refused; every other old code loads untouched, and no load reinterprets a depth. A range change appends one `RANGE_CHANGES` entry, bumps `CURRENT_RANGE_EPOCH`, and re-authors `AUTO_STATES` so each lane on the moved dial keeps its swept Hz: its new depth is the half-span, on the new dial, of the values it reached on the old one. `built_in_cutoff_sweeps_cover_the_hz_they_did_before_the_dial_widened` pins the result for the cutoff widening. Container version 2 is the only one that exists — all v1 plumbing is deleted and a v1 code is rejected outright with `UnsupportedVersion`, never silently decoded as empty state. Control ids are interned as `SONG_ID_TABLE` indexes and continuous values stored as a u16 taper position, so those round-trip within one u16 step rather than exactly; discrete rows and the `PowerOfTwo`/`BeatGrid` step ladders stay exact, as do all beat-valued automation fields, `LfoRoute::seed`, and every tonal-sequence field. A table-indexed discrete row whose dial order is not its saved identity declares `ControlSpec::song_values`; the codec writes the table's value for the dial position and maps it back on read (`song_values_cover_every_dial_position`). Unknown *record types* stay skippable on purpose — that is how a code from a newer build still loads everything else — while an unknown *container version* is a hard error.

- Module slots (`fluid/module.rs`, design in `docs/proposals/2026-07-30-module-slot-addressing.md`): all eight voice layers plus Master carry `MODULE_SLOTS` anonymous slots addressed by stable storage IDs. **A module's identity is a stored value, never part of a control id** — ids are permanent `SONG_ID_TABLE` entries, so putting the catalog in the id space would cost a fresh block per module forever. `MODULE_CATALOG` is append-only because saved slots store its indexes. Domain (pre/post) comes from the loaded module, not the slot index. Only modules with complete behavior for a layer may appear in its add palette; retained catalog indexes without DSP stay unavailable. Each loaded module collapses to one row, named by `ModuleKind::collapsed_field` — Cutoff for Filter, Threshold for Compression, Amount for other families; a module with a detail drill (`ModuleKind::has_detail`) labels that row `Name ›`, Enter opens its reusable `Navigation::Module` detail (and `Space k` enters Filter detail on Cutoff), `/` exposes the same dotted sub-context, and Esc restores the parent. Adding a module from the palette lands the cursor on its row; a newly added Filter or Compression opens its detail on Amount so the first arrow can bring its dry mix in. A detail lists the collapsed field first (test-enforced). Pads' effects remain siblings of musical controls and never enter chord drills. Delay owns Amount/Left Time/Right Time/Feedback/Vintage; `T` independently converts each time between Sync and Free, and a time change crossfades to the new tap position over a fixed window rather than sliding the read head, so tempo-synced retargeting never pitch-bends. Reverb owns Amount/Size/Damping. Compression owns Threshold/Amount/Ratio/Release/Makeup. Filter detail owns Cutoff/Amount/Resonance/Type. Palette insertion gives it Amount 0% for exact dry passthrough and focuses that Amount in the detail; preloaded factory Filters retain their authored fully wet amounts and cutoff. Ordinary browsing edits Filter Cutoff on the collapsed row. `Space k` opens Filter detail on Cutoff, including after insertion. Cutoff spans `FILTER_CUTOFF_MIN_HZ..FILTER_CUTOFF_MAX_HZ` (20..20000 Hz, Log2) and is stored exactly in song codes; the factory Perc/Bass/Kick Filters stay at 8 kHz, since codes that never touched them carry no cutoff. A direct row edit of Type (arrow, typed value, reset) goes through `switch_filter_type`: Low-pass ↔ High-pass mirrors the cutoff (`min * max / hz`) so a transparent filter stays transparent; Band-pass keeps it. Palette value entry, randomize, and automation set Type without the mirror. Swing is amount-only; Drunken has Amount and Pace in its drill. Drive's drill is Amount, Type (`fx::drive::DRIVE_TYPES`: Soft/Hard/Fold, stored in `feedback`, append-only), Bias (`time`) and Dry (`right_time`). Every Drive field's 0 is the original sound (Soft, unbiased, fully wet), so codes saved before the drill decode unchanged; the blend is Dry, not Mix, for that reason (`every_built_in_drive_keeps_the_original_curve`). One slot-addressed post-DSP bank executes Drive/Reverb/Delay/Compression/Filter in chain order on every voice layer and Master. Slot FX state is runtime-only: a loaded song starts every delay line and reverb silent and rebuilds the tail from playback. A processor whose slot stops asking for its family — emptied, or swapped for another module — is never dropped outright; it moves to `ModuleFxBank::retiring`, keeps running on the live input while its contribution crossfades back to dry over `LEVEL_RAMP_MS`, and only then is released. It fades using `last_loaded`, the slot's fields from the last frame it was loaded, since the live slot has already been cleared by then and its zeroed Amount would silence the tail being faded. Dropping instead of retiring cuts a live tail to zero in one sample and leaves the processor's buffers frozen rather than decayed, so refilling the slot replays the previous take (`removing_a_module_fades_its_tail_instead_of_cutting_it`, `re_adding_a_module_does_not_resurrect_the_previous_tail`, `replacing_a_module_fades_the_outgoing_one`). Swing and Drunken hold no tail and so have nothing to retire; Drive is a `SlotFx` for its ADAA history, DC blocker and Type crossfade, and retires like the others. Serializing those buffers put one Delay slot past a million characters in a song code.
- Master Swing is an optional module offered as `/global swing`; its 50–75% dial supplies the swing amount to voice layers without a local Swing module, except Kick. Kick stays straight under Master Swing; only a local Kick Swing moves its off-slots. A local Swing at 0 overrides the Master fallback on every other layer. Drunken is an optional pre-trigger module on Master and every voice layer. Its collapsed Amount reads 0–100% and starts at 0; Enter opens Amount and Pace (4–12 nominal trigger hits, default 7). A local Drunken slot overrides Master for its layer, including Amount 0; without one, Master is the fallback. Layer palette searches rank that layer's Drunken before Master. Each layer has its own deterministic phase and variable-length triangular lag waves of at least four triggers. At 100%, the maximum lag is the lesser of 10% of a beat and 35% of that layer's trigger interval; Amount scales it. The 31-trigger seeded cells vary the rise/fall length without requiring mutable random state, and a saved code carries the running wave's beat offset. Drunken codes from epochs before 4 are refused rather than reinterpreted, including prototype wave codes from the branch-only epoch 3. Master beat telemetry, OSC voice input, and Pad chord progression stay on transport time.
- Retired controls (`pad.reverb_mix`, `tonal.reverb_mix`, `arp.reverb_mix`, `clap.room`, `perc.swing`, `tonal.swing`, `arp.swing`, `pad.swing`, `master.tune`, `tonal.randomness`, `bass.drive`, `kick.drive`, `kick.filter`, `clap.filter`, `pad.trigger`, `pad.gate_beats`, `pad.offset_beats`, `pad.step1`..`pad.step16`, all bespoke Master Drive/Compression ids, and all 10 former MIDI controls) keep their append-only `SONG_ID_TABLE` slots but are gone from the registry, and nothing translates them. A code naming any table id that no live spec claims is refused with `SongCodeError::RetiredControl`; an index *past* the table's end is a control from a newer build and stays skipped, which is the only reason the two cases are distinguished (`reject_retired_control`, `song.rs`). Retiring a control therefore invalidates every code that set it — re-author `AUTO_STATES` by decoding on the last build that understood the id and re-encoding on the new one, carrying its value, the chain slot it belonged in, and any LFO routed at it (`auto.rs`'s `AUTO_STATES` doc comment works the conversion). The default template preloads Pads Reverb at 80%, Tonal Reverb at 10%, Arp Reverb at 0%, Bass/Kick/Master Drive, and Master Compression; Clap starts with a factory Filter and Swing remains optional. `ModuleTimingPlan` derives pre-trigger Swing and Drunken fields. Post effects read slot state directly.
- Every slider must use its full visual throw. Continuous controls map value to bar position through `Taper` (`Linear`, `Log2`, or `Exp(n)`). Irregular `Step::BeatGrid`, `Step::PowerOfTwo`, and LFO-rate ladders divide the bar by reachable arrow rungs instead of raw numeric magnitude; exact values between rungs interpolate within that segment. The base value and every modulation marker must use the same mapping. `ControlItem` carries real value/min/max plus step and taper; never bake position transforms into stored values. A continuous tapered dial with a plain `Step::Linear` steps in position space and stores full precision.
- Every time control reads through the shared `secs(seconds)` formatter (whole ms below 1 s, 2-dp seconds above) — ms-stored controls pass `ms/1000.0`. Time dials normally use `Taper::Exp(TIME_TAPER)` so they step consistently regardless of storage unit; retune that common feel from the single constant. Perc Attack uses `Taper::Exp(1.5)`: its first of 48 position steps is about 3 ms over a 0–1000 ms range, while `TIME_TAPER` would leave several arrow presses displaying 0 ms from the required zero default. Beat-grid/power-of-two musical controls keep their musical stepping and are left off the exp taper.
- Every continuous automation field, including LFO, envelope, and inline step targets, derives its range, arrow stepping, numeric entry, reset target, and dial scale from a `FieldSpec` table row, never from a per-field match arm. `Stepping` names how one press moves it (linear, snapped to the field's grid, along an explicit rung ladder, along the musical beat grid, or an equal fraction of a tapered throw) and `Entry` is the registry's own numeric-entry vocabulary. A random roll lands through `FieldSpec::value_at_ratio` (position space, or an equal share per rung) and writes the stored value directly, never through the numeric-entry setters, whose percent parse would divide it by 100. Only the discrete fields (LFO shape, envelope trigger) stay outside the tables: they are enums cycled by index, and a roll gives each entry an equal share (`index_at_ratio`). Display strings stay on `LfoRoute`/`EnvelopeRoute`, not in the spec. Arrow navigation clamps inside the open submenu; Escape closes it.
- LFO `rate` spans 0.125–64 beats; fresh lanes start at 1 beat, and saved rates restore unchanged. Arrow steps use quarter-beat rungs through 4, then 8/12/16/32/64; each rung gets an equal share of the bar and numeric entry remains exact within the range. A live rate edit never rewrites offset: the old and new globally anchored waveforms hand off at their next crossing (`LfoPickup`), after which the new rate follows the shared transport grid. Equal rates with zero offset share phase across every control.
- `FluidEngine` applies a two-second startup mix fade; keep `startup_fade_reaches_full_gain_in_two_seconds` and the seeded golden-render checksum aligned with intentional changes to that window.
- Auto morph keeps Kick and Bass in the hold, then drops both for every percentage transition and restores their destination levels on the next song downbeat. Both use `MorphState::drop_gain_at`: fade over the last `LEVEL_RAMP_MS` (30 ms) of the hold, silence after automation and each layer's module chain throughout the crossing, then open together on landing. Modulation and effect tails cannot leak through. On landing, the engine settles both Level smoothers to their destination values before rendering the first notes; Kick captures gain at trigger time, so a return ramp would silence that entire hit. Perc and Clap still cut on the transition downbeat when the target has no drums and may fade in independently.
- Per-slider `f` (LFO) and `e` (envelope) open or cycle that lane family. `Shift+F`/`Shift+E` adds and opens a lane, `x` removes only the open lane, and Escape closes the editor. `r` while browsing is `RandomizeSelected`: it sets the selected control to a random point on its own dial through `ControlSpec::apply_ratio` (position space for tapered rows, an equal share per rung for the `BeatGrid`/`PowerOfTwo` ladders, rounded onto the table for discrete rows), so a time dial is as likely to land short as long; inside an automation editor the same key is `RandomizeAutomationRow`: `FieldOp::Randomize` rolls exactly the row under the cursor (one LFO/envelope field, one Steps target, or the parent control on row 0), and on a random shape's Shape row it rerolls the seed and keeps the shape (footer `r reseed`, else `r random`). `Shift+R` is `RandomizeScope`: in browsing it uses the coordinator's pre-action visible-row projection, so it randomizes exactly the current page or drill (including a module detail) in one session transaction; in an automation editor it randomizes every field of the open route, including the LFO Steps configuration and random seed, except that with the LFO cursor on a Steps staircase row (`edit::lfo_steps_selected`: count, glide, or a value) it rolls only the live step values (`LfoRoute::randomize_step_values`) and the footer reads `Shift+R randomize steps`. The roll comes from `EffectExecutor`'s one `StdRng` — entropy-seeded in production, `REPLAY_RNG_SEED` in replay — so a replayed trace rolls the same values twice. Do not add voice-specific LFO/envelope controls to core slider tabs.
- New lanes start at zero amount and persist until explicitly removed, including untouched lanes. Closing an editor or navigating away never deletes a lane. Song codes retain zero-amount LFOs and envelopes in stack order; amount zero is silent, not a deletion marker. Each family is capped at four lanes per control, including silent lanes; hitting the cap returns a visible interaction failure, and `x` frees the selected lane's slot.

Tab completes a recipe name without opening value entry. Repeated Tremolo reuses its authored shape/rate lane even after Amount is raised; other recipes add another lane. Existing silent lanes count toward the cap. A failed preflight leaves auto and the session unchanged. The fallible transaction rechecks capacity before publication. Recipe identity is never saved: the lanes use the existing song codec and editors. Successful recipe application opens the new LFO editor on Amount; a failed preflight publishes no lane or control change.

Parameter edits leave it unchanged. This conservative guard also refuses a pending module recipe after an unrelated slot changes; reopening `/` captures the current structure. Non-module targets keep their stable control id. The Jump leader grammar is unchanged.
- Audio hot paths reuse one effective-controls working copy. `AutomationPlan::restore` reverses its scalar writes after rendering, before retiring faded routes; every apply/restore pair must complete before the next sample. The engine rebuilds plans by retained session Arc identity, never by comparing or cloning automation maps. De-click coefficients are cached per sample rate. `ModuleTimingPlan` caches timing-slot indexes by effective kind bits, including automated topology changes, and reads current amounts each sample. Planned mute checks read the session only when the ramp target changes or the boundary arrives; cancellation is observed at the normal control cadence and rechecked transactionally at commit.

UI markers show this semantic target. `AutomationPlan` applies the same sum through one 3 ms de-clicker after composition, preserving continuity across envelope retriggers, route edits, and lane removal without storing that transient in song codes.
- Automation colour identifies the modulator family: LFO lanes are pink and envelope lanes are green. Envelope polarity changes direction, never colour. Envelope previews use the same signed, centred height mapping as LFO previews: a negative zero-attack envelope starts below neutral and rises back to it.
- Grid-timing controls carry `LfoSnap` in their `ControlSpec` (intervals snap modulation to power-of-two subdivisions, offsets to their step grid). `GridTrigger` may pull a scheduled hit earlier when a reshaped grid lands sooner (so a denser grid never starves), but a live reshape cannot schedule within half an interval of the hit already emitted (`earliest_hit`, floored on `last_hit_beat`). Drunken progression advances by slot when the scheduled grid still matches, so close swung hits are not dropped or repeated during tempo glides. Grids that move later latch at the next fire.
- Chord length (`pad.chord_bars`, `0.0625..=16.0` bars) stores bars for the pad/bass engines but displays and accepts numeric entry in beats (`0.25..=64` beats, including `1/4 beat` and `1/2 beat` sub-bar steps); typed values convert to bars and snap to the power-of-two grid.
- Manual Gain and Continuous edits use registry-derived `ControlSmoothers` in `FluidEngine`, with the shared 30 ms eased ramp. Allocate each unique base Gain/Continuous row once, then consult its contextual kind when targets change: compressor Threshold/Ratio, filter Cutoff/Resonance, and reverb Size smooth alongside gains. Timing and Discrete rows, plus Swing Amount, arrive immediately; Delay keeps its own tap crossfade. Replacing a module settles all its fields to the incoming values instead of interpolating across different units. Filter Type and its mirrored Cutoff land together without a cutoff sweep under the new response. Only active ramps run per sample; their index list is preallocated and refreshed at control cadence. Ramps start settled on load and are transient audio state, never song-code payload.
- Perc applies a fixed `0.5 / 3.0` source trim to both hits and continuous noise so its useful Level range sits above the first dial step. Built-in morph states compensate their Perc Level and Level-LFO depths by three through the current song encoder; no endpoint clips, and their authored balance stays intact.
- A layer's Level scales its engine's summed output every sample; it is never captured into a voice at trigger time. Capturing it means the fader cannot reach notes already sounding, which on Tonal/Arp (up to 6 s of decay) left a layer audible long after it was pulled to zero while Mute cut instantly (`tonal_level_ducks_notes_that_are_already_sounding`). Level scales the *output* of any tone-shaping filter the engine owns, never its input: `TonalLowCut` is a high pass, and feeding it an abruptly silenced signal discharges its state as a decaying thump. Tonal and Arp still skip creating a voice at a Level of exactly 0, which keeps a silent layer from accumulating inaudible voices without affecting the fader's reach.
- Master Key (`master.key`, `MasterKey` in `voice/mod.rs`) replaced Tune. Its dial is Home (every progression keeps its authored key, the default and the only value that leaves a built-in unchanged), then C through B. `MasterKey::shift(progression)` is the semitone move from that progression's home tonic (`progression_tonic_pitch_class`, a once-built table `FluidEngine::new` fills before audio) to the chosen pitch class by the shortest way round, -6 through +5; Custom's home is A. The shift is resolved per voice from the progression that voice is sounding, at the moment it builds a note: Pad from its own cursor after it ticks, Bass/Arp/Lead from their `ProgressionFollower`, Tonal from the progression the engine hands it. So a progression change or morph landing never plays one note of the new chord under the old shift, and a key change lands on the next trigger. Voice `next` and `PadEngine::new` take the `MasterKey`; the helpers underneath still take the resolved semitone `tune`. External OSC voice input resolves against `FluidEngine`'s Pad cursor in `route_osc_voice_input`. `PadEngine::new` is the one constructor that must be handed the live key rather than assuming Home: it voices the opening chord, which then holds for a whole `chord_bars` with its release bleeding into the next, so a song code carrying a key would otherwise open in the authored key against a transposed Bass/Tonal/Arp (`pad_voices_its_opening_chord_in_the_master_key`). The screen names the key the song sounds in: the home-key header, the Progression row ("Cm · Drift"), and every letter chord name carry the shift; Roman numerals read against the home key and ignore it. `master.tune` is retired (`RetiredControl("master.tune")`, `a_code_setting_the_retired_master_tune_is_refused`) and built-in songs 5 and 6, which carried +5 over Custom, were re-authored as key D. OSC pitch classes still report the authored pitch, not the sounding one (deferred).
- TUI automation edits must go through `EffectExecutor`, which publishes through the aggregate live-session transaction on every mutation.

- Pitched voices (Pad, Bass, Tonal, Arp, Lead) route note numbers through `voice::note_hz` (`midi_to_hz` under the resolved key shift); unpitched voices (Perc, Kick, Clap) do not.
- Tonal separates trigger density from phrase shape: `tonal.rate_beats` controls note trigger spacing; `tonal.step_interval_beats` is the stable cycle-length ID (`Cycle` inside the `Phrase ›` drill) for phrase wrapping and evolution boundaries. `tonal.offset_beats` moves the cycle-length window forward through the phrase without phase-shifting the trigger grid, so Cycle 2 + Offset 1 plays phrase beats 2–3. `tonal.phrase` (`Phrase ›` on the root page, `Phrase` inside `TonalDrill::Pattern`; presets 0–3 plus `Custom = 4`) selects a preset contour or `Custom`. `tonal.steps` (1–16, default 8) and `tonal.step1`..`tonal.step16` (`-1..=9`: `Tie = -1`, `Rest = 0`, degrees `1..=9`) expose the 16-step sequence inside `TonalDrill::Pattern`; selecting a preset phrase seeds `tonal.steps` and `tonal.step1..16` from `TONAL_PHRASES`, while manual step edits switch `tonal.phrase` to `Custom`. `tonal.follow` (`Chord = 0`, `Scale = 1`, default `Scale`) selects whether degrees resolve against the sounding Pad chord tones or the progression home scale. On a `Rest` step no note triggers; on a `Tie` step the most recently triggered active `TonalVoice` extends its decay by one step interval without re-attacking.
- Tonal synth selection lives in `tonal.synth_type`; it changes the voice created for new tonal notes while preserving the shared phrase/timing/master-key/reverb path. Exploration variants may differ in harmonic tables, spectral tilt, and pitch-scaled harmonic decay; keep piano-family profiles warm and non-metallic unless the user explicitly asks for FM-like brightness.
- Tonal's built-in phrases, evolved notes, and random pool stay in their existing 1-based degree coordinates in the song code. `TonalEngine::next` maps each selected degree by `tonal.follow` (`Scale`: the sounding Pad cursor's progression home tonic/mode; `Chord`: the sounding Pad chord tones via `ProgressionFollower`), then applies `tonal.octave` as whole octaves before `note_hz`. A requested progression edit changes Tonal's home when Pad adopts it at the next chord boundary; chord-window edits and borrowed chords do not change that home scale. Every engine, including headless renders, starts Tonal from the song's saved sequence; only live audio publishes later evolution back to the session. This keeps phrase contour and saved evolution state when the progression changes; Arp still derives its own pitches from sounding Pad chords.
- Every tonal/arp note is a single attack+decay shape via the shared `attack_decay_gain` helper (Sine and all piano-family profiles): the gain ramps in over `attack` seconds, then falls from the peak to silence over `decay` seconds, so a note's whole sounding life is `attack + decay` and the envelope reaches exactly 0 there (no click at voice death). The step grid (`tonal.rate_beats`/`arp.rate_beats`) only spaces triggers — it never bounds a note's length — so notes overlap freely when `decay` outlasts the step (both engines accumulate polyphonic voices). `decay` is floored at `TONAL_DECAY_MIN` (10 ms) so the UI can't request a hard, clicking cut; only the decay curve's shape exponent (`PianoProfile::body_power`, or the sine voice's fixed sqrt taper) stays profile-owned character. Clap and perc already embody this decay-to-zero model (their inline `decay_ms` fades) and are the reference the tonal/arp envelope was unified to. Pad and Bass are deliberately separate (long sustained chords; mono voice-stealing) and keep their own envelopes.
- Tonal owns a slight fixed low cut before engine mixing so its low notes sit above sub/bass energy without requiring a user-facing control.
- Pad, Tonal, Clap, and Arp emit dry voice output. Any Reverb is owned exclusively by that layer's shared module chain; there is no voice-local or ambient-send reverb path.
- Arp follows the Pad's current chord or progression home scale (`arp.follow`: `Chord = 0`, `Scale = 1`, default `Chord`) without reaching into `PadEngine` directly: it holds a `ProgressionFollower` (pad.rs; Bass and Lead hold the same one) whose `ProgressionCursor` keeps the Pad's phrase, reads chord tones via `pad_chord_tones` (or scale tones via `lead_reach`), and plays its 16-step sequence (`arp.steps` 1–16, `arp.step1`..`arp.step16` with `Tie = -1`, `Rest = 0`, and tones `1..=12` across 1–3 octave span) on its `arp.rate_beats` grid, phase-shifted by `arp.offset_beats` (default 0, matching the Level/Interval/Offset idiom shared with Perc/Bass/Kick/Tonal/Clap). Selecting a preset `arp.pattern` (`Up`, `Down`, `Up-Down`, `Random`) or changing `arp.octaves` while on a preset seeds `arp.steps` and `arp.step1..16`; manual step edits switch `arp.pattern` to `Custom` (`4.0`). `arp.evolve_rate` (like `tonal.evolve_rate`, `lead.evolve_rate`, and `pad.evolve_rate`) visibly mutates active steps in `LiveSessionSnapshot` at loop cycle boundaries when `> 0%`. Its synth character lives in `arp.type` (`ArpControls::voice_type`), reusing Tonal's `TonalVoice`/`TONAL_SYNTH_TYPES`/`piano_profile` path (same Sine + 9 piano-profile set and labels as `tonal.synth_type`); default `6.0` ("Pluck") matches the arp's former hardcoded profile byte-for-byte. `arp.gain` defaults to 0 (silent) so adding the voice never changes an existing song or default startup. When the chord or octave span changes mid-cycle, the cycle position is clamped into the new tone list rather than reset, avoiding a click.
- Lead (`voice/lead.rs`, `LeadControls`, `Tab::Lead` between Arp and Master) is the one hands-on melodic voice: a mono additive voice whose character is `lead.type` (`LEAD_TYPES`: Saw/Square/Soft/Pure/Reed, each a `LeadRecipe` of eight signed harmonic gains plus a trim that `lead_types_render_at_a_matched_level` holds within 10%; read per sample, so a Type edit reshapes the sounding note), with a one-pole pitch glide (`lead.glide`, `glide_coefficient`) and an attack/decay life per note, retriggered in place so a new note slides from the last without a click. It plays a step lane: `lead.steps` (1–16 live steps) and `lead.step1`…`step16`, each a `Tie` (`-1`), a `Rest` (`0`), or one of `LEAD_TONE_COUNT` (9) tones (`1..=9`), under `lead.pattern` (`LEAD_PATTERNS`: `Off`, `Steady`, `Call`, `Climb`, `Groove`, `Custom`, default `Steady`; `Pattern ›` on the root page, `Pattern` inside `LeadDrill::Pattern`). Off (`0.0`) is the solo position — the lane is silent, played keys still sound, and the trigger keeps ticking so turning it back on resumes on the clock's step. Selecting a preset (`Steady`, `Call`, `Climb`, `Groove`) seeds `lead.steps` and `lead.step1..16` from `LEAD_PATTERN_PRESETS`; manual step edits, `evolve_steps`, and `lead_capture` switch `lead.pattern` to `Custom` (`5.0`). It is a discrete control like any other, so a Steps LFO can gate or cycle the pattern in bars. A `Tie` step sustains the sounding note (`LeadShape { hold: true }` across tied steps, releasing when the next step is not `Tie`) without retriggering or re-emitting OSC, and extends the initial note's OSC `gate_beats` across consecutive tied steps. There is no armed record state: a phrase enters the lane by capture after it was played (`lead_capture`: the presses since the last bar of silence, within the last 16 steps, each snapped to its nearest step, on the shortest of 4/8/16 steps that holds them, placed at `absolute step mod length` so the loop plays back where it was played), the way Ableton's Capture MIDI keeps a take nobody armed. A tone is an index into the Lead's reach (`LeadReach`), which `lead.follow` picks: Chord is the Pad's current four voiced tones through the shared `ProgressionFollower`/`pad_chord_tones` path, so keys move as chords move; Scale is the seven-note explicit home mode in `Progression::home_mode`, rooted at the first chord for built-ins and at A for Custom; borrowed chords and chord-window edits leave it unchanged. Tones past the reach wrap an octave (a four-note reach reads `1 2 3 4 1' 2' 3' 4' 1''`, `lead_tone_label`), then `lead.octave` lifts the note. The sequence controls (`Pattern`, `Follow`, `Octave`, `Rate`, `Steps`, `Offset`, `Evolve`, and `Step 1..N`) live in the page-local pattern drill (`LeadDrill::Pattern`, `lead_tab_controls`, opened by Enter on `Pattern ›`), never on the root page; only the live steps show there, and `DEFAULT_LEAD_STEPS` rests past the default length so lengthening the lane adds silence. The active lane row carries the same amber `♪` follower marker as the chord progression; an LFO in its `Steps` shape marks its active step too. Both markers derive from their transport clocks, so neither adds persisted state. A retrigger on a sounding voice resumes the attack from the current level (`Adsr::start_at`) with the phase untouched, so fast playing is click-free; the default glide (30 ms) is a slide between held notes, not lag under a line. The step a hit plays is derived from the transport (shared `lane_step_at`, like the LFO staircase), so there is no lane position to persist. Its "slightly distorted" character is a factory Drive slot at 0.1, not a bespoke control. Trims are set so full Level sits below the Bass (`lead_at_full_level_sits_under_the_bass`): a bright driven lead reads louder than it measures, and the fader's useful range has to be the whole bar. `lead.level` defaults to 0 and its audio triggers nothing at that level, while OSC output can still send the lane and played keys. Play mode (`LeadEngine::observe`/`with_play_state`) sounds a pressed tone on the next sample, sliding from whatever the lane is playing; `LeadPlayState::held` sustains it (`LeadShape { hold }` sets the ADSR sustain to 1 and the release to `decay`), the flag dropping releases it, and the lane yields while a key is held so the player owns the voice; the footer names a 0 level so a silent keyboard is not mistaken for a dead one.
- `LeadControls::default` selects Soft (`lead.type = 2.0`) for a fresh session; Lead Level still starts at zero.
- The song-code mute record is indexed by `Tab::mute_bit`, a per-tab bit assigned once in the order tabs were added (Master is 7, Lead is 8), never by discriminant, and is `MUTE_BYTES` wide. Adding a tab mid-strip therefore cannot move a saved mute onto another tab; a shorter payload from an older build simply carries no bit for the newer tabs.
- Built-in progressions are `voice::PROGRESSIONS`: eight `ChordSlotControls` presets, authored symbols used for the progression label, an independent Bass line, a mood, and a permanent `song_value`. Every sounding source tone comes from `voice/chord.rs`; presets have no raw-note fallback. `pad_chord_name` derives each visible chord name from the effective notes and their declared roles. `progression_label` retains the authored key and mood. A–H save values 0–7, Custom saves 8, and additions take the next unused value; dial order may change. Unknown saved values are refused. Growing the progression dial appends a range epoch. Progressions from song value 9 on retain a common tone across the full loop and each half's loop; E–H retain one across the full loop (`voice_led_progressions_hold_a_tone_through_every_window`).
- `PadControls::chord_slot` resolves an authored preset or its optional override across 16 steps (`CHORD_SLOTS = 16`, wrapping the 8-chord preset progression across steps 9–16 by default); `edit_chord_slot` seeds only the first edited slot. The fixed per-progression banks retain edits across selection changes. Authored banks live behind `Arc`; UI edits copy on write. `AutomationPlan::apply` first resets a fixed 16-slot `EvaluatedChords` scratch bank, so effective setters never call `Arc::make_mut` or allocate in the callback. Morph skips effective chord setters and transfers the authored Arc at landing. The encoder refuses evaluated controls, and history/session snapshots use authored controls. `PadEngine` caches resolved notes until the full chord definition changes. Viewing, naming, saving and palette navigation never seed them. Custom keeps its separate 16-slot `chord_slots` bank. `ControlSpec::stored_as` supplies raw Custom access for the snapshot codec; ordinary getters/setters operate on the effective selection. `/restore chord` captures a permanent progression value, slot and field snapshot, then clears only that base override after context validation. Custom restores that slot's default. Restore closes editor navigation while keeping its LFO/envelope lanes and performs normal Motion takeover. The typed `/add extension` action reveals a live-only second row; only editing its value authors a change.
- The shared builder prioritizes root, third/suspension, Extension, Extension 2, then fifth, keeping at most four distinct pitch classes. Duplicate extensions and a conflicting second seventh are omitted. Fifth Scale retains the established natural-root fifth; Perfect selects seven semitones; Omit removes that role. Forced Quality choices are labelled third overrides. Close preserves existing Custom inversion and diatonic unison handling; Stack rotates distinct roles before octave doubling; Open, Wide and Drop-3 spread the clean stack. Slash Bass choices use an explicit bass plus the first three selected roles. The slot header names the resulting four source tones, including Close's introduced tones. Root/Accidental remain A-minor editor pitch coordinates; the explicit home tonic/mode model remains the separate 0064 seam. Detailed choices and audition cases: `docs/proposals/2026-10-03-shared-chord-builder.md`.
- Sparse override record 13 (version 2) stores a version, count and permanent progression/slot keys (`slot < 16`) with `step_mode` (`Rest = 0`, `Tie = 1`, `Active = 2`) plus all eight chord fields. Decode rejects older versions, malformed, duplicate, unknown, truncated and trailing entries before publishing a song; encode rejects nonfinite, fractional and out-of-range fields through registry validation. Active and inactive banks round-trip independently of snapshot record order. Epoch 6 refuses older modulation on every chord-slot field, including Root and Accidental whose numeric ranges stayed fixed but became effective on built-ins; Epoch 10 (`SEQUENCE_UNIFICATION_EPOCH`) covers the 16-step chord window, sub-bar `pad.chord_bars`, and `-1..=9` Lead step range. Container v2 still skips unknown records: edited built-in progressions require a build that understands record 13; older binaries cannot preserve these edits. Automation resolves the effective progression before its slot fields, including fading selector routes, on the audio working copy only.
- `pad.chord_count` (1–16, default 8, `Steps` inside `ChordDrill::Progression`) and `pad.chord_offset` (0–15, `Offset` inside `ChordDrill::Progression`) choose the chord window for every progression. `ChordWindow` wraps 16 table slots; `ProgressionCursor`, held directly by Pad and through `ProgressionFollower` by Bass/Arp/Lead/Tonal, owns their shared clock and tracks `active_slot_at` across `Tie` steps plus `is_rest_at` on `Rest` steps. Length, Count and Offset edits wait for the sounding chord to end; the old length times the pending boundary and the new length times later ones. If the current slot survives, its new successor plays next; otherwise use the old next slot if present, then the new offset. Progression selection restarts at offset. A load starts a fresh phrase at beat zero. `pad_chord_tones` and `bass_root_note` resolve table slots. Built-in Bass preserves its authored pitch until Root/Accidental changes, then transposes by that exact root delta; other chord fields leave the authored pedal/register intact. Custom Bass follows its root. The progression drill (`ChordDrill::Progression`, opened by Enter on `Progression ›`) lists `Progression`, `Steps`, `Length`, `Offset`, `Notes`, and the active `Step 1 › .. Step N ›` rows (`pad.chord1_state`..`pad.chord16_state`: `Tie` `—`, `Rest`, or `Chord` with actual chord name, Built-in/Edited state, and sounding badge `♪`); Enter on `Step k ›` opens `ChordDrill::Slot(k - 1)` with `Root` and concise chord fields. `/` destinations round-trip by stable control ID even when Root appears in both drills.
- Bass character lives in `bass.type` (`BassControls::voice_type`, `BASS_TYPES`, append-only): index 0 (`Sub`) is the legacy voice and the default — its DSP path must stay byte-identical to a pre-`bass.type` render. 1 `Saw` is a brighter additive-harmonic character, 2 `Pluck` a shorter one with an octave click. 3 `FM` (a 1:1 pair whose index decays from 16, over a steady 1:2 body pair), 4 `Fold` (a sine into the Drive module's antialiased triangle folder, drive decaying from 7× to unity), and 5 `Acid` (`synth::oscillator::PolyBlepSaw` into `synth::filter::SvfLowpass` sweeping from 26× the note to 2×) each open bright and settle toward the fundamental; their sweeps last a share of Decay. All six share the trigger/rhythm, pitch (`midi_to_hz` + Master Key), and module chain, and stay within 2× of each other's RMS (`bass_types_produce_differing_but_comparably_balanced_audio`) under `MAX_BASS_PEAK` 1.6. Growing the dial took `BASS_TYPE_EXPANSION_EPOCH` (7). `bass.punch` (0–100%, default 0) is captured at note start: every type starts up to 12 semitones sharp and falls back with a 12 ms time constant (`PunchSweep`), and FM/Fold/Acid also start up to 3×/2×/2.5× brighter. At 0 no sweep exists, so Punch-free notes keep their unscaled oscillator path. `bass_type_audition` (ignored) writes every type with and without Punch to `$NOOISE_AUDITION_DIR`.
- Bass is monophonic (`BassEngine::voice: Option<BassVoice>` in `bass.rs`): each rhythm-grid hit hard-cuts whatever is currently sounding and starts the new note immediately, regardless of `decay_time`. The replaced voice isn't dropped instantly (that clicks) — it rings down over a fixed short (`BASS_MONO_FADE_SECONDS`, ~3ms) `fading_voice` slot, independent of the voice's own envelope. This applies identically to every `bass.type` character. No user-facing control; this is not a voice pool.
- Post-synthesis filtering runs through the shared `ModuleFxBank` at a stable layer/slot identity. The Filter module owns its left/right state and accepts only its persisted amount, cutoff, resonance, and type fields. A zero Amount is an exact dry bypass. Shared Filters replace the retired `perc.filter`, `bass.cutoff`, `kick.filter`, and `clap.filter` controls and are preloaded into slot 1 on all four layers. Clap's is fully wet at `CLAP_FACTORY_FILTER_CUTOFF_HZ` (3170 Hz), the cutoff of a fit to the retired one-pole's rendered default; the voice itself now emits unfiltered noise. Bass and Kick Drive occupy slot 2. Kick keeps fixed voice-local filters as part of each character; the shared module owns the user-facing sweep.
- Pad character lives in `pad.type` (`PadControls::voice_type`): one `PadTone` runs the shared `PadOscStack` into the shared soft-clipper, and a character is exactly one `PadStage` between them plus one output trim after. Index 0 (`Warm`) is the legacy tone and default; `PadStage::None` with a 1.0 trim keeps its original render byte-identical (`pad_type_zero_keeps_the_legacy_warm_signal_path`). `Dark` adds a lowpass, `Glass` a two-octave shimmer, `Choir` a moving upper partial, `Hollow` a sub-octave tone, and `Tape` a lowpass with slow level drift. A Type edit swaps the stage in place on already-sounding tones without restarting the envelopes. Only phrase controls (chord length, count, progression, offset) wait for the chord boundary. Each chord step's `StepMode` (`Rest`, `Tie`, `Active`) drives rhythmic and sustained phrasing directly from the 16-step chord progression: an `Active` step voices its chord (and re-attacks if the same slot repeats on a 1-step window), a `Tie` step sustains the sounding chord across the step boundary without re-attacking or re-emitting OSC notes, and a `Rest` step releases the sounding chord into `releasing_tones`, sends OSC note-offs, and suppresses chord-following triggers (`Bass` and `Arp` skip triggering, `Lead` and `Tonal` in `Follow = Chord` mode skip triggering while `Follow = Scale` keeps playing). All six characters share chord selection, pans, and the dry-output/engine-owned-reverb contract, and are gain-authored to comparable levels.
- `pad.chord_notes` (`Notes` inside `ChordDrill::Progression`) chooses 2–5 output voices (default 4) through the shared audio/OSC `pad_voicing` path. Preserve its saved positional meaning: 2 selects source positions 1 and 3, 3 selects the first three, 4 selects all four, and 5 adds source position 1 two octaves up. Thinning may omit a third or extension; the added fifth voice doubles the lowest source and does not recover an omitted role. Spacing and slash bass come from the four-tone builder first. Bass, Arp and Lead keep their underlying source behavior. A count edit revoices active Pads immediately.
- Kick character lives in `kick.type` (`KickControls::voice_type`, `KickVoice`): Sub/Warm/Wood/Felt retain indexes 0-3 and their existing voicings; Sub is the default and its legacy DSP path stays byte-identical. 909/Deep/Dust occupy indexes 4-6. Every type shares `KickEngine`'s trigger grid and the same Type row. The original four use `KickFmBody` and `KickVoiceCore`; Sub/Warm/Felt use `LowpassKickVoice` recipes, and Wood uses its bandpass path. The new three use `AnalogKickVoice`: one sine resonator with an exponential pitch sweep, a separate longer amplitude decay, a short beater impulse, decaying click noise, and onset-only second harmonic. It adds no sample playback or saved runtime state.
- `kick_types_render_at_a_matched_level` holds every character near Sub's rendered RMS; `no_kick_type_exceeds_the_headroom_budget` bounds peak. `kick_909_has_a_short_attack_and_audible_bass_tail` and `kick_909_moves_from_low_mids_into_bass_instead_of_holding_a_second_tone` protect the measured attack-to-tail shape. The 909 reference is the open Oramics Detroit TR-909 `kick.wav`; it is an analysis target, not a bundled asset. Wood retains its calibrated fixed-filter gain.
- Warm/Wood/Felt stay soft and textural. 909/Deep/Dust are more present options reached through the same Type row; Deep extends the bass ring and Dust adds more onset. Shared Drive remains the effect for extra distortion. Growing the `kick.type` dial requires a `RANGE_CHANGES` epoch so old modulation depths are refused rather than silently spanning new characters.
- Every voice/Master `Level` row and every active Compression slot's `Threshold` row (`Amount > 0`) renders a live telemetry meter across the top edge of its knob bar (on the hub, layer page, and module detail): `FluidEngine` publishes ballistics-smoothed per-tab RMS (`FluidTelemetry::levels` / `TelemetryView::levels`), and `ModuleFxBank` folds each slot's deepest compressor gain per `LEVEL_BLOCK`, applies instant-attack/0.3 s-release ballistics on the audio thread, and publishes non-negative dB through `FluidTelemetry::gain_reduction_bits` (`TelemetryView::gain_reduction_db`, indexed `module_layer_index(tab) * MODULE_SLOTS + slot`). Meters are never written into `ControlItem::display`, so the palette stays pure, and retiring processors are not metered.
- Master Drive and Compression are ordinary preloaded shared modules. They use the same root/detail interaction, DSP primitives, registry semantics, automation, and song persistence as copies on voice layers; no bespoke Master compression drill or release row exists.
- Voice RNGs must stay reseedable via `FluidEngine::reseed` so `nooise render --seed` stays byte-reproducible. `a_seeded_render_repeats_itself_exactly` pins that in every profile. The separate `GOLDEN_RENDER_CHECKSUM` tripwire for unintended DSP-math drift is `#[cfg(debug_assertions)]`: debug and release evaluate the same float expressions differently and diverge by an ULP partway through the render, so one constant cannot hold for both. Re-bless it from a debug run.
- Passive update checks must never block the TUI or audio callback; keep crates.io/network work off the main loop and show no message on failure.
- `nooise update` checks crates.io before invoking Cargo; do not force reinstall when the installed version is already current.
- `nooise auto` morphs by owning and rewriting both the live `FluidControls` and `AutomationState`, using the same clone-modify-store path as the UI. Every row's crossing (`Move::Tempo`/`Glide`/`Drop`/`Wait`/`Snap`/`Stagger`) is decided in one place, `move_of`; a new must-not-blend rule is a line there, never a branch in `controls_at`. Control behavior follows registry `ControlKind`. `--bars` requests an approximate total leg duration: round its `HOLD_FRACTION` (2/3) hold to the nearest whole outgoing phrase and its remaining crossing to the nearest whole outgoing phrase, at least one phrase each. A phrase is the shared `ChordWindow` count times Chord Length, even if Pads are silent. Leg lengths may differ by direction; precomputed cumulative starts locate any loop without advancing mutable progress. `Gain`/`Continuous` glide across the transition window; `Timing`/`Discrete` snap through `spec.quantize`. Harmony rows (`pad.progression`, `master.key`, and `pad.chord*`, including custom definitions and voicing) and their addressed automation hold the outgoing state through the crossing, then change together at landing. The complete Custom and per-preset override banks transfer with that landing; generic effective setters must not seed overrides during a morph. `TimingContext::morph_phrase_start` anchors every `ProgressionCursor` to the incoming window's first chord on that landing, including unchanged progressions with different windows. Arp pattern still snaps at the start of the crossing. Ordinary manual chord edits retain their existing boundary/successor behavior. Morph boundaries use the trigger grid's `GRID_BEAT_EPSILON` tolerance so a hit cannot fire against the previous section because of clock rounding. The engine bypasses its 128-sample control cadence at hold/crossing/landing boundaries; the regular writer uses absolute eighth-note buckets so delayed ticks do not accumulate drift. Any slot holding Swing in either endpoint waits through the crossing and changes its kind and Amount together on the next song downbeat. When a module moves between slots on one layer, both slots and their addressed automation wait until that downbeat so the module remains present exactly once. Other module slots whose kind or delay clock differs between endpoints (`swapped_slots`) snap on the transition downbeat, because their Time/Amount rows change meaning with the module and blending them is never valid (a Reverb's size dragged toward a Filter's Hz, wet mix swelling under a rising Level); other grid params stagger at `STAGGER_STEP_BARS` offsets after it. `AutomationState::morph` pairs lanes by family and ordinal. Each lane's amount glides while its curve and trigger fields snap together at the transition downbeat; lanes present on only one endpoint fade in or out. The AUTO footer reports `MorphState::position_at`: the song sounding on its own through the hold, and `playing → next` with a percentage only once the leg is actually crossing, so it never announces a transition that has not started; a live toggle labels its initial session snapshot `LIVE`. Any manual control or automation edit exits auto. A live toggle requests `LIVE_FIRST_LEG_BARS` (16 bars) for its first leg, rounded with the same phrase rule; long phrases can extend it. It reads the sounding phrase anchor from the audio-owned `LiveSession` clock so the toggle itself never becomes a new downbeat. Subsequent legs use the configured request (`DEFAULT_AUTO_BARS` 64). Transport restart rebuilds the first leg at beat zero. The CLI names one thing one way: a **song** is either a built-in number or an `n1_` code, and `nooise <SONG>` plays it — `nooise 9`, `nooise 9,10,11` (morphing through them and looping), or `nooise n1_...`. `nooise auto` is every built-in song; `--bars` applies to both. `nooise auto --from N` (also `nooise --from N`) rotates the full loop to start at built-in song N, continues through the last song, wraps to 1, and retains original song numbers. Missing or invalid numbers are errors; `--from` conflicts with a separate song selection and non-auto subcommands. Auto off/on still uses the canonical built-in ordering and labels. A song number outside the built-in range is an error, never a clamp. `auto` deliberately takes no positional so an old `nooise auto 4` fails loudly rather than silently meaning song four. Add a morph target with `just add-morph <code>`; the helper inserts at the `AUTO_STATES` marker, rejects duplicate codes, verifies decoding, and commits only `auto.rs`.

- Auto tempo uses a precomputed `TempoMove` per leg. A faster/slower ratio up to `TEMPO_MATCH_RATIO` (1.1875, a 15 BPM gap at 80 BPM) eases directly across the kickless crossing with `smoothstep`. Larger gaps try half or double the destination BPM within the supported tempo range and the same ratio of the source; the crossing glides to that bridge tempo and the landing adopts the destination's authored BPM. Otherwise tempo holds until a landing jump. This ratio is the current musical default for audition, not a user control. `MorphState::tempo_at` drives both published BPM and the audio clock; the engine evaluates it every sample and bypasses manual-tempo smoothing during auto so landing jumps happen on the downbeat. Beat position never resets, and outgoing phrase counts stay fixed even as their duration in seconds changes.

- The panel's two top inner rows center the home key above the fixed chord sequence during normal browsing, including on the Hub and at 46x11. `ui.rs` reads one frame's Pad controls and chord telemetry; its amber highlight advances across the sequence with the sounding chord, so phrasing remains visible outside scrolling controls.
- `Progression::home_mode` is the built-in key's scale contract. Custom's home remains A minor. `progression_home` supplies both the display label and Lead Scale pitches; a borrowed chord affects chord-following voices without expanding that scale.
- Chord naming (`ChordNames`: Letters/Roman) is a live-only display choice in `LiveSessionSnapshot::chord_names`, set by the `/roman` and `/letters` operations (`Operation::ChordNames` → `InteractionEffect::SetChordNames`; idempotent, so repeating applies the same state, and never an edit, so it neither exits auto nor enters the MRU). It never reaches the audio thread or a song code, and a loaded code always opens in letters. `pad_chord_name` takes the naming; the header, the progression row's chord line, the progression drill, and the chord editor title all read it from the one session generation. `roman_chord_name` writes each root's degree in the progression's own `home_mode` (so a minor key reads i III iv VI VII, with no accidental on any diatonic root), flat on the degree above or sharp on the degree below otherwise (nothing is flat of the tonic, so a leading tone is `#VII`), upper case for a major chord and lower case for minor or diminished (`ii°`). A chord with no third (power, suspended) takes the case of the home mode's own triad on that degree. A slash bass is its degree in the home mode (`I/3`). Custom's home is A minor. `every_built_in_progression_opens_on_its_tonic` pins each built-in's first chord to its home key.
- `voice::lane_step_at` resolves Perc, Bass, Kick, Tonal, Clap, Arp, and Lead pattern steps from transport beat, rate (`0.125..=4.0` beats), offset (`0.0..=4.0` beats), and live step count (`1..=16`). Every sequencer track labels its step duration `"Rate"` and its phase shift `"Offset"`. `bass.rhythm` (`Pattern ›` on the root page, `Pattern` inside `BassDrill::Pattern`; presets `Steady`, `Offbeat`, `Broken`, `Groove`, plus `Custom = 4`) seeds `bass.steps` and `bass.step1..16` (`-1..=9`: `Tie = -1`, `Rest = 0`, degrees `1..=9` resolved against `bass.follow`: `Chord = 0` or `Scale = 1`), where `Chord` degree 1 preserves `bass_root_note` and consecutive `Tie` steps hold the note at peak via `Adsr::set_hold` before decaying.
- Perc's `perc.pattern` (`Pattern ›` on the root page; presets `Steady`, `Offbeat`, `Broken`, `Groove`, `Continuous = 4`, `Custom = 5`), Kick's `kick.pattern` (`Steady`, `Offbeat`, `Broken`, `Groove`, `Custom = 4`), and Clap's `clap.pattern` (`Steady`, `Offbeat`, `Broken`, `Groove`, `Custom = 4`) seed their respective `steps` (1–16) and `step1..16` (`-1..=1`: `Tie = -1`, `Rest = 0`, `Hit = 1`), where `Steady` hits on every step (`[1.0; 16]`) and consecutive `Tie` steps sustain the hit envelope at peak before decaying. Perc's `perc.attack_ms` is a browsable 0–1000 ms row before Decay. Its position-space taper gives a roughly 3 ms first arrow step from the zero default and coarser steps near the top. Each hit rises from its first sample to peak across Attack, then runs its full existing Decay; overlapping hits keep independent envelopes. Zero Attack preserves the original PCM, and Continuous mode (`perc.pattern == 4`) bypasses hit envelopes. The chosen Attack and sequence fields persist through their append-only song IDs.

## Conventions

Crate-wide rules. A change that breaks one is a change to this section, not an exception.

- **Visibility**: `pub(crate)` on everything, fields included. Never bare `pub` — the crate is a binary and exports nothing, so bare `pub` only misleads about reach.
- **Errors**: typed enums with `Display` + `std::error::Error`, and `source()` where a cause exists. No `Result<_, String>` and no stringly channels: an error's identity is data, its prose is `Display`. A payload string is only for text a foreign backend produced (`ClipboardError`, `AudioStartError::Backend`); the variant still names which step failed. User-facing notices format with `{error}`, never `{error:?}`.
- **Infallible lookups**: `.expect()` only where a table test enforces the claim, and the doc comment names that test. Everything else routes through the same failure path as its neighbours.
- **Module docs**: every file opens with `//!` saying what it owns. Not `// ====` banners — those remain only as in-file section separators.
- **Test-only helpers**: gate with `#[cfg(test)]`. Never bare `pub(crate)` plus a dead-code allow; `#[allow(dead_code)]`/`expect(dead_code)` is reserved for enum variants in a closed vocabulary that cannot be conditionally compiled.
- **DSP process fns** take one `…Params` struct, never loose arguments. Details in `fx/AGENTS.md`.
- **Bounds**: `ControlSpec::contextual` is the single source of a control's live range, step, taper, and entry semantics. Nothing downstream re-clamps; pin a DSP's assumed range with a test instead of restating it.
- **Naming**: an index is `*_index` or `index`, never `idx`. Multi-field positions get a named struct (`ModuleScope`), not an unnamed tuple.
- **`use super::*;`** is the deliberate internal prelude of the `fluid` tree: `fluid/mod.rs` re-exports its submodules and each submodule glob-imports them back. This is the one sanctioned wildcard import.

## Verification

- `just test` (cargo test, default and `--features link`) covers engine logic and the control registry; tests live in `fluid/tests.rs`.
- `just check` runs clippy across all targets, default and `--features link`; both builds must stay warning-free.
- `RUSTC_WRAPPER= NOOISE_CHORD_EVIDENCE=target/oct3-chords/current cargo test --release --locked chord_builder_audio_evidence -- --ignored --nocapture` exports deterministic built-in-song PCM hashes plus Ache/Float loop WAVs; its metadata records timing and seed. It never blesses fixtures.
- `nooise render --seconds N --seed N --out X.wav` (or `just render`) renders audio headlessly for DSP verification — same seed must produce byte-identical output.
