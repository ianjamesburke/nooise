## New user intake while audit was in progress — unverified requests

The user asked the team to **wait and capture more thoughts**. These are requests to refine the next plan, not accepted implementation or release requirements yet. They should be reconciled with current behavior before sprint commitment:

- **Named songs, optional server, cues/morph:** CLI currently accepts a code or built-in number (`src/main.rs`), while 0074's `~/.nooise/songs/` library is only a proposal. Define the smallest named-song storage and retrieval contract separately from an optional server/state-cue/morph proof of concept. A server must not become necessary for plain keyboard play.
- **Link and OSC:** Link is only in `feat/ableton-link`, with optional `rusty_link`; its `Cargo.toml` explicitly says enabling `link` compiles C++ and requires CMake/libclang. Main has `--osc` telemetry and older musical-hit event commits, but the requested chord/phrase timing feed needs a concrete message/timing acceptance check. Neither experiment is on the current release path merely because its branch exists.
- **Transport restart:** `docs/PERFORMANCE.md` and engine currently specify Shift+P stop then play starts at bar one, resetting voice grids and phrase position. The user's reported start/stop phrase-restart bug needs a reproducible sequence against that contract; distinguish an implementation failure from a changed desired resume behavior.
- **Modulation recipes:** Current `Drift` is documented/constructed as 16 beats, 25% (`src/fluid/recipe.rs`); the requested four beats, 10% differs. Current recipe application closes the editor, while the user wants inert 0% creation and Amount focus. Establish the intended sound-first gesture, persistence and exact amount semantics before changing every recipe, then check whether 0% makes the new operation discoverable/playable under the North Star.
- **Harmony/tracks:** The user now emphasizes an explicit scale and progression, two unified melodic layers supporting arp/sequence/lead use, and Tonal staying in key. Main has a newer home-key model but not the 0065 shared-track format; `temp-tonal-harmony` uses a different derived chord-window pool. Reconcile this intake with the unmerged 0064 design before changing the engine.
- **Timing feel:** Global Swing and Drunken timing are on main. The user wants downbeat Kick/snare preserved under global Swing and proposes a half-strength Drunken effect for Kick; existing `GridTrigger` scheduling and tests prove some timing properties, but no hands-on evaluation of this exact groove was found. Treat the half-strength idea as proposed, requiring rendered and musical comparison.
- **Morphing automation:** The user wants LFO Amount to glide during morphs. Current general morph timing is already under 0050 review; inspect the current morph policy for Amount and specify whether this is a regression or new interpolation requirement before editing.
