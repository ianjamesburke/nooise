## Execution contract

- One implementation agent per step, one focused `wtp add -b ...` worktree per step, root `main` kept as reference. No two agents edit the same worktree or overlapping source paths concurrently. Do not merge old experimental branches wholesale or touch dirty worktrees. Use current root and nearest source/docs AGENTS.md chain before each edit, then DOX closeout. Each agent reports branch/path, exact change, checks, and what remains for Ian's ear. Bring accepted slices together sequentially; independent investigations may run concurrently, but integration must use the then-current main.
- Baseline gates for code: focused behavior tests, `cargo build --locked`, `cargo test --locked`, `cargo fmt --check`, strict `cargo clippy --all-targets` with zero warnings, `git diff --check`; retry `RUSTC_WRAPPER=` for inherited sccache permission failures. Test production input/OSC paths where relevant. Deterministic render evidence supports, but never substitutes for, musical audition.
- A current report is a reproduction target, not proof the present engine path is broken. If the behavior cannot be reproduced, preserve the documented behavior and return an evidence-backed diagnosis rather than change unrelated semantics. No broad 0065 shared-track/song-format rewrite this sprint. Song codes must preserve chosen runtime musical state and remain compact; no silent migration or MIDI field deletion.
